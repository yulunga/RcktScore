## Current Product State

`RcktScore` v2 is the active app in this repository.

Current stack:

- React + Vite frontend in `frontend/`
- Python AWS Lambda backend in `backend/`
- Supabase Postgres as the primary datastore
- AWS SAM for backend deployment
- native iOS client in `mobile/ios/`
- native Android/Compose foundation in `mobile/android/`; product feature
  implementation has not started yet

The old Flask code in `version1/` is reference-only and should not be treated as the active product.

## Current Release Posture

The repository is still pre-launch. Web and backend flows are in late beta, and
the native iOS app is in active device hardening rather than production release
readiness.

What is real and implemented:

- org-user login with opaque backend sessions: web sessions use a host-only `HttpOnly`, `Secure`, `SameSite=Strict` `__Host-hitnscore_session` cookie, while iOS and Android retain JSON bearer tokens
- browser authentication uses exact-origin credentialed CORS for `https://app.hitnscore.com`; cookie-authenticated POST/PUT/PATCH/DELETE requests require the server-session CSRF value in `X-CSRF-Token` and an exact matching `Origin`. The web client keeps CSRF only in memory, rebuilds non-secret identity state through `/session/status`, and stores no authentication token in browser storage. Protected routes wait behind a branded session-restoration screen until that initial check completes, preventing a refresh from briefly rendering or navigating through the login page. Migration `048_browser_cookie_csrf_sessions.sql` adds CSRF state and revokes legacy JavaScript-readable web/root-admin sessions at cutover
- one active organisation-user session is retained per identity across web and mobile. A forced login revokes the previous device session; web, iOS and Android refresh `/session/status` every five seconds while active (and immediately on focus/foreground) so role, plan and sport-access changes appear without another login. Clients clear local credentials on `SESSION_REPLACED`, while every tenant-specific request still re-authorizes the selected organisation membership and role server-side
- identity-first multi-organisation login uses one password per normalized email identity: the supplied password must verify against every non-null membership hash before any approved membership is returned. A partial match fails closed with `PASSWORD_RESET_REQUIRED` and emails an identity-wide reset; successful legacy rows that contain different salted hashes for the same password are rewritten to one fresh hash in the login transaction. Club membership create/edit flows cannot accept administrator-chosen passwords; new identities receive a set-password invitation, ordinary resets update every membership and revoke active sessions, and only a dedicated first-account setup token may approve its token-holding membership. Login opens one session immediately, preferring the approved personal membership and otherwise the first approved club. The legacy sign-in membership chooser remains available through `IdentityFirstLoginEnabled=false`

## Security Notes

- org-user session enforcement is real in `backend/common/session_logic.py`
- org-user sessions expire after 30 days by default, configurable from one to 90 days, and cached native sessions cannot be reopened after their server-provided expiry
- reconnect-safe scoring action UUIDs are recorded in `match_action_receipts`; duplicate retries return current match state without repeating the mutation
- every state-derived match mutation locks its `matches` row with `SELECT ... FOR UPDATE` before rebuilding event state; the action receipt, event/undo, summary columns, and any completed tournament-fixture result are committed or rolled back together
- scoring and organisation endpoints are tenant-aware through backend authorization checks
- sport visibility is enforced before match creation as the intersection of platform client access, organisation `enabled_sports`, and per-membership web/iOS access
- Tournament Manager access is club-only, requires an explicit `tournament_organization_features.web_enabled` record and is enforced by the backend in addition to conditional web navigation
- tournament detail reads tolerate briefly missing `tournament_draws`/`tournament_matches` tables by deriving display-only draw labels or returning empty fixture lists, but migrations `032_tournament_event_options.sql`, `034_tournament_draw_matches.sql`, `035_tournament_draw_publication.sql` and `036_tournament_match_results.sql` are required before event/draw/publication/result writes; public draw-key responses are read-only and exclude emails and account identifiers
- root-admin login issues a separate `__Host-hitnscore_root_admin` HttpOnly cookie whose opaque value is represented only by a hash in `root_admin_sessions`; Root Admin has independent CSRF state, an eight-hour default lifetime, and `/root_admin/session/status` restoration without browser token storage. The Ground Control keeps the current route behind the branded restoration screen until that check finishes. Reused organisation routes use `X-HitnScore-Session: root_admin` only to select the Root Admin cookie when both cookies coexist; the header grants no trust and full server-side session validation remains mandatory
- the former `x-root-admin-request` trust-header bypass has been removed
- root-admin authorization is implemented, but public-route rate limiting, broader audit logging, and other launch hardening still remain
- Standard spectator display uses a court name matching the game-details text, content-sized header/history rows, and viewport-scaled scores (up to 24rem) positioned higher in the available area
- do not describe WebSocket live display as production-complete
